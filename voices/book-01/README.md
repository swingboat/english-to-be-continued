## 写入每集 HTML 的规则

每个人物先定义声音，再在生成的每集 HTML 中提供清楚可见的“人物与配音设定”表。表格逐人列出姓名、性别、年龄感、性格、音色特征、参考语音文件名与项目内路径、确认状态（已选定／暂定采用／待确认），依据本目录的 `cast.json` 和实际参考文件填写。

HTML 中为本集涉及人物内嵌可离线播放的参考语音，并附对应试听文本。播放器不自动播放，注明这是人物音色参考。

明确英文解说使用的人物音色，区分解说、内心独白与角色对白。人物的声音跨集保持一致，画外音、电话和采访回放沿用本人音色；当句的紧张、疲惫、轻声等表演要求写在对应分镜。新增人物先补齐声音设定与参考语音，再在 HTML 中说明。

## 固定人物声音的办法

本地现有模型是 **VoiceDesign**，用于把描述转成候选声音。相同 seed 和相似提示词有助于复现同一实验，但不构成跨文本的固定说话人身份。

音色选定后，保留对应 WAV 与准确文本作为参考，再使用 **Qwen3-TTS Base** 的参考音频克隆能力产生后续台词。[Qwen 官方的 Voice Design then Clone 流程](https://github.com/QwenLM/Qwen3-TTS#voice-design-then-clone)说明了先设计参考声音、再用它复用音色的做法。本机此次仅复用现有 VoiceDesign 模型，尚未配置 Base 克隆流程。

小帅与分身具有相同外貌和生成前身份设定。本轮二者使用相同的 `voice_identity` 和 seed，并保持接近的基础声线描述，使用同一段英文方便比较。**这不保证生成结果已经是同一个人的声音。** 后续优先采用同一条选定参考音色，通过台词内容、停顿与表演节奏表现性格差异，跨句跨集的相似度仍需要试听核对。

妈妈的疲惫、学生的紧张等属于具体场景的表演状态。人物基准声音使用正常交流状态，避免把单集情绪固化到所有台词中。

## 生成命令

从项目根目录运行，复用现有 Python 环境、缓存模型与 FFmpeg：

```sh
/Users/huyin/Swingboat/audio-research/experiments/tts/qwen3-tts/.venv/bin/python voices/book-01/generate.py
```

只生成配置中指定的人物：

```sh
/Users/huyin/Swingboat/audio-research/experiments/tts/qwen3-tts/.venv/bin/python voices/book-01/generate.py --only 小帅 小帅的分身
```

输出直接写入人物姓名目录。已有当前文件时脚本停止，避免意外改动已选定的声音；有意更换人物音色时，先更新 `cast.json`、清理该人物待替换的文件并更新其选定记录，再生成。脚本不再创建版本目录。

查看配置和输出路径而不生成音频：

```sh
/Users/huyin/Swingboat/audio-research/experiments/tts/qwen3-tts/.venv/bin/python voices/book-01/generate.py --dry-run
```

模型修订固定为 `5c390979e4b93af5f2932f90742ca99c7dd04687`，参数沿用参考实验：temperature 0.7、top_p 0.9、top_k 50、repetition_penalty 1.05，本轮短样本 max_tokens 700。生成串行执行，避免同时占用 GPU。脚本检查波形非空、数值有限、非静音和峰值未超满幅，并验证 MP3 完整解码、采样率及单声道。每人的实际耗时、时长、软件版本及文件哈希保存在其 `生成记录.json`。
